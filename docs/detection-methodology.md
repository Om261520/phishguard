# PhishGuard Detection Methodology

## 1. Zero-Interaction Static Analysis Philosophy
PhishGuard is architected to perform **static URL decomposition**. Unlike dynamic sandboxes that make live HTTP connections to arbitrary endpoints, static analysis has distinct operational advantages:

1. **Zero Malware Exposure:** The scanning server is never exposed to drive-by browser exploits, zero-days, or executable payloads.
2. **Evasion Resistance:** Threat actors often employ anti-bot fingerprinting to serve fake benign pages when they detect scanner IPs. Static lexical analysis inspects the true URL payload parameters and domain topology without triggering attacker cloaking.
3. **Instant Latency:** Static extraction runs in sub-milliseconds ($< 2\text{ms}$), providing real-time triage for SOC analysts.

## 2. Feature Extraction Mathematics & Heuristics

### Shannon Character Entropy
Domain entropy is utilized to identify Algorithmically Generated Domains (DGA) or staging hosts generated by automated attack toolkits.
$$H(X) = -\sum_{i=1}^{n} p(x_i) \log_2 p(x_i)$$
* **Benign Domains:** Typically exhibit entropy values between $2.0$ and $3.5$ (e.g., `google.com` $\approx 2.12$, `wikipedia.org` $\approx 3.12$).
* **DGA / Obfuscated Domains:** Exhibit entropy $> 3.8$ (e.g., `xk98qwz71mnpl0a8s7d6f5.biz` $\approx 4.19$).

### Lexical & Structural Indicators
* **Length Vectors:** Total URL length, domain length, path length.
* **Punctuation Density:** Count of dots, hyphens, and special characters (`@`, `?`, `=`, `&`, `%`, `_`).
* **Protocol & Transport:** Unencrypted HTTP vs HTTPS (noting that HTTPS alone does not establish legitimacy).
* **Numeric Density:** Ratio of digits in hostnames ($>25\%$ flagged as machine-generated).
* **Target Impersonation:** Detection of high-value brands (PayPal, Microsoft, Apple, Google, Netflix, Chase, etc.) in non-authoritative hostnames.
* **Token Obfuscation:** Hexadecimal percent-encoding patterns (`%xx`).
* **Open Redirect Vectors:** Query parameter detection (`url=`, `redirect=`, `next=`, `dest=`).

## 4. Multi-Factor Risk Scoring Formula
The final composite risk score (0–100) is calculated through a calibrated non-linear fusion:

$$\text{Base Score} = (0.45 \times \text{Rule Score}) + (0.45 \times (\text{ML Probability} \times 100))$$

$$\text{Final Risk Score} = \min(\max(\text{Base Score} + \text{Compounding Synergy Boosts}, 0), 100)$$

### Classification Thresholds
* **0 – 29:** `SAFE` (Clean structural profile, minimal or zero heuristic flags)
* **30 – 59:** `SUSPICIOUS` (Anomalous parameters or moderate entropy detected)
* **60 – 79:** `HIGH RISK / SUSPICIOUS` (Multiple compounding flags requiring SOC investigation)
* **80 – 100:** `PHISHING` (High-confidence active threat vector / brand impersonation)
